# 场景定义模块

本目录包含所有业务场景的API和工作流定义，已从原始的 `system_definitions_final.py` 拆分为独立的场景文件。

## 目录结构

```
scene/
├── __init__.py          # 场景聚合模块，提供统一访问接口
├── medical.py           # 医疗场景（挂号、就诊、检查、住院等）
├── ecommerce.py         # 电商场景（购物、订单、支付、物流等）
├── train_ticket.py      # 火车票场景（购票、改签、退票等）
├── logistics.py         # 物流场景（仓储、配送、调度等）
├── finance.py           # 财务场景（预算、报销、付款、审批等）
├── hrm.py              # 人力资源场景（考勤、请假、工资、培训等）
├── education.py        # 教育场景（选课、成绩、考试、图书等）
├── noise.py            # 干扰域场景（游戏、社交、智能家居等）
└── README.md           # 本文档
```

## 使用方法

### 导入所有场景定义

```python
from Model.scene import DEFINITIONS

# 访问特定场景
medical_scene = DEFINITIONS["medical"]
ecommerce_scene = DEFINITIONS["ecommerce"]
```

### 导入单个场景

```python
from Model.scene import MEDICAL_SCENE, ECOMMERCE_SCENE

# 访问场景的APIs
medical_apis = MEDICAL_SCENE["apis"]
medical_workflows = MEDICAL_SCENE["workflows"]
```

## 场景说明

### 1. 医疗场景 (medical.py)
**核心功能：**
- 10个API：科室查询、医生排班、挂号、取消、报告查询、处方查询、取药、住院申请、病历查询
- 5个工作流：门诊挂号、检查报告查询、取消挂号、药房取药、住院申请

**触发关键词：** 挂号、预约、看病、就诊、检查报告、取药、住院

### 2. 电商场景 (ecommerce.py)
**核心功能：**
- 17个API：商品搜索、详情、购物车管理、地址管理、优惠券、订单创建、查询、取消、支付、物流跟踪、退款、评价
- 5个工作流：购物流程、下单结算、订单查询、退款申请、商品评价

**触发关键词：** 买、购买、下单、购物、结算、支付、订单、物流、退款、评价

### 3. 火车票场景 (train_ticket.py)
**核心功能：**
- 12个API：车站搜索、车次查询、详情、乘车人管理、购票、订单查询、支付、退票、改签、保险
- 4个工作流：购票流程、订单查询、退票流程、改签流程

**触发关键词：** 买票、购票、订票、火车票、查询订单、退票、改签

### 4. 物流场景 (logistics.py)
**核心功能：**
- 15个API：仓库管理、库存查询、入库、出库、司机管理、车辆定位、路线规划、派单、配送状态、签收、异常上报
- 5个工作流：入库作业、出库作业、配送派单、配送跟踪、异常上报

**触发关键词：** 入库、出库、发货、拣货、派单、配送、跟踪、物流状态

### 5. 财务场景 (finance.py)
**核心功能：**
- 15个API：预算管理、报销提交、查询、取消、审批、付款、发票上传、验真、对账单、财务报表
- 5个工作流：费用报销、报销单查询、预算查询、审批流程、付款申请

**触发关键词：** 报销、费用报销、预算查询、审批、付款

### 6. 人力资源场景 (hrm.py)
**核心功能：**
- 17个API：员工档案、考勤打卡、请假管理、工资查询、招聘、培训、绩效考核
- 6个工作流：打卡流程、请假流程、请假查询、工资查询、档案查询、培训报名

**触发关键词：** 打卡、签到、考勤、请假、休假、工资、员工档案、培训

### 7. 教育场景 (education.py)
**核心功能：**
- 20个API：课程管理、选课、退课、成绩查询、考试安排、图书借阅、奖学金、宿舍管理
- 6个工作流：选课流程、成绩查询、考试安排查询、图书借阅、图书归还、奖学金申请

**触发关键词：** 选课、报名课程、查成绩、成绩查询、考试安排、借书、还书、奖学金

### 8. 干扰域场景 (noise.py)
**核心功能：**
- 游戏：购买皮肤、排行榜、匹配
- 社交：发布动态、关注、时间线、点赞
- 智能家居：开关灯、温度设置、设备管理、场景触发

**用途：** 测试模型的抗干扰能力和场景识别准确性

## API定义结构

每个API包含以下字段：
```python
{
    "id": "api_xxx",              # API唯一标识
    "path": "/api/xxx",           # API路径
    "method": "GET/POST/PUT/DELETE",  # HTTP方法
    "desc": "API描述",             # 功能描述
    "request": [                  # 请求参数列表
        {
            "name": "参数名",
            "type": "参数类型",
            "label": "参数标签",
            "required": True/False
        }
    ],
    "response": [                 # 响应字段列表
        {
            "name": "字段名",
            "type": "字段类型",
            "desc": "字段描述"
        }
    ]
}
```

## 工作流定义结构

每个工作流包含以下字段：
```python
{
    "id": "wf_xxx",               # 工作流唯一标识
    "name": "工作流名称",          # 显示名称
    "desc": "工作流描述",          # 功能描述
    "trigger_keywords": [],       # 触发关键词列表
    "nodes": [                    # 节点列表
        {
            "id": "n_xxx",        # 节点ID
            "type": "user_input/api_call/display",  # 节点类型
            "desc": "节点描述",
            "ai_instruction": "AI指令",  # AI生成界面的指导
            "fields": [],         # 用户输入字段（仅user_input类型）
            "api_id": "api_xxx",  # 调用的API（仅api_call类型）
            "next": "n_yyy"       # 下一个节点ID
        }
    ]
}
```

## 扩展说明

### 添加新场景
1. 在 `scene/` 目录下创建新的场景文件，如 `new_scene.py`
2. 定义场景字典，包含 `apis` 和 `workflows` 两个键
3. 在 `__init__.py` 中导入并添加到 `DEFINITIONS` 字典

### 扩展现有场景
1. 打开对应的场景文件
2. 在 `apis` 列表中添加新的API定义
3. 在 `workflows` 列表中添加新的工作流定义
4. 确保API的 `id` 和工作流的 `id` 在全局唯一
